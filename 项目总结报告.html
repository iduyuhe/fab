一、项目背景与目标

起点是一个由 数字孪生（3D 厂房）+ MES（制造执行）+ EAP（设备协议网关） 三系统组成的雏形平台，已具备设备状态展示、基础派工、SECS/GEM 通信能力。但存在四项关键数据缺口：工单/批次无持久化、缺乏主数据服务、无质量数据源、无 Historian 历史。

升级目标：以"事件驱动"为骨架，将该平台从"三系统演示"升级为覆盖 设备层 → 执行层 → 质量层 → 预测层 → 计划层 → 企业层 的全链路智能制造平台，每一层均具备可验证的数据闭环。

六、关键技术决策与坑

6.1 原生 ERP 而非接口

用户明确旧 ERP 陈旧，决定不做接口、做原生。验证可行：独立进程 + 独立 DB 订阅 MES 事件流，零翻译零耦合，制造核心四模块（库存/采购/销售/成本）全部事件驱动联动。

6.2 稳定性三连坑（已根治）

  • 静态页面异步读超时 → 改为启动读入内存缓存
  • 逐事件同步写 SQLite 阻塞事件循环 → 改为批量队列 + 800ms flush
  • BEGIN/COMMIT 事务与业务写同连接锁冲突 → database is locked 崩溃 → 启用 WAL 模式 + busy_timeout，flush 失败丢弃不重试；并加事件循环心跳诊断

6.3 其他修正

  • VM/成本计价：加速模式下 durH 为模拟秒 → 改用标准工艺步时表（与 core modAvgH 同源）
  • SPC 演示设备需真实存在（METRO 从 141 起，非 001）
  • SO 默认价 0 → 应收 0，改为自动取成品单价
  • 3D 联动沿用现有 highlight/byId/WS 管线，零架构改动接入

八、后续可扩展方向

主线已收官，以下为可选增强：
  • ERP 轻量财务：在制造核心四模块之上加简单利润汇总（不碰总账借贷）
  • APS 滚动优化：接实时 SPC/HOLD 状态动态重排，实现闭环排程
  • 孪生-报警深度联动：点击 3D 报警设备直接穿透到 SPC 监控组 / PdM 风险详情
  • 多工厂/多产品线：当前为单 fab 模型，可扩展为产线级拓扑
  • 对外数据开放：以 /api 形式向 BI 工具开放，替代旧报表系统

九、结论

本项目将初始的"三系统演示"升级为 覆盖设备层到企业层的事件驱动智能制造平台。五大闭环（执行/质量/预测/计划/企业）全部以真实数据验证：虚拟量测 MAPE 1.87%、SPC 自动停线闭环、批次成本实时归集、APS 瓶颈与交期承诺、3D SPC 报警联动。系统经 289 次请求压力测试零超时，六进程稳定运行。

核心经验：以事件总线为骨架、各子系统独立进程 + 独立 DB 订阅联动，既避免单点耦合，又彻底规避了数据库锁冲突类稳定性问题——这是该平台可继续横向扩展（更多智能模块）的架构基础。

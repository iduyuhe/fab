2. 关键实证：3D 孪生确实接通 MES（非假活）

担心点：默认合成场景的机台 id 与 MES 真实 tool id 命名空间对不上 → byId.get(ev.id) 永远 undefined → 单台 3D 永不更新、只是假活。

3. 本次修复 / 增强

问题：合成孪生初始状态是 pickStatus() 随机值，要等 MES toolStatus 逐台覆盖（~30s）才收敛到真实，加载瞬间存在"账实空窗"。

修复：新增 seedFromMES()（仅 src=mes）：加载即从 /api/tools 拉真实 status/util/wph/wafers/chambers/recipe 铺底并同步信标颜色，updateStats + 日志。STATUS 做了兜底映射（MES 若有 SETUP 等未定义态 → 归 IDLE），防越界崩溃。

改动在 twin3d/index.html 的 if(src==='mes') 块内，未改架构；module script 已 node --check 通过。

4. 诚实修正 & 仍可改进

诚实修正：上一轮（"孪生装备模块核查"）我对 twin3d 仅做了语法检查 + 复活 verify_p7/p8 算法自验脚本，没有读孪生主体即称"默认 src=mes 接通主轴"。该结论方向正确，但缺乏实证、背景缺孪生内容。本轮已补齐。

仍可改进（非缺陷）：

  • 真实 BIM/glTF（?model=）接管后，设备语义绑定走 moduleResolver 的网格名规则，事件仍按合成 id 空间 byId 命中；若真实网格名无法映射到同一 id 空间，真实模型下孪生事件不会高亮。默认合成场景不受影响。
  • 单台指标（util/wph）仅在点开 info 面板时刷新，未在 3D 上做常驻浮标；属可视化取舍，非数据断点。

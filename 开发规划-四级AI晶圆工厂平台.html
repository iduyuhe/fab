规划目标

把现有演示级平台（事件驱动主线 + 三级孪生 + 五大引擎 + 原生 ERP），按"社区 → 教学 → 专业 → 工厂"四级， 借助 Agent 团队 并行开发，演进为以 AI Agent 为核心的 AI 芯片晶圆厂智能企业操作系统。 本规划只定义蓝图、分工与里程碑，不在此阶段编写业务代码。

一、产品架构总图（目标态）

┌─────────────────────────────────────────────────────────────┐
│                    四级交付外壳（逐级升档）                    │
│   L1 社区(开源沙盘) → L2 教学(课程实验) → L3 专业(工程工具) → L4 工厂(真实部署) │
├─────────────────────────────────────────────────────────────┤
│                    AI Agent 团队（三层）                       │
│   战略层(厂长大脑) · 领域层(质量/设备/量测/排程/成本专家) · 执行层(设备协作者)  │
├─────────────────────────────────────────────────────────────┤
│                    核心能力层（五级引擎 + 孪生）                 │
│   SPC/FDC · PdM · VM · APS · ERP · 三级数字孪生 · what-if 仿真    │
├─────────────────────────────────────────────────────────────┤
│                    数据主线层（事件驱动）                       │
│   WIP Engine → 事件总线(WS) → 各订阅方 · 拓扑/主数据 · 时序/关系存储  │
├─────────────────────────────────────────────────────────────┤
│                    接入层（标准 / 协议）                        │
│   SECS/GEM(E37) · HSMS · OPC-UA · EDA · ISA-95 · B2MML          │
└─────────────────────────────────────────────────────────────┘
设计原则：下层不依赖上层；四级外壳共享同一核心层；Agent 团队只编排"领域层 + 战略层"能力，执行层对接设备。 用 L4 的架构思想（微服务、ISA-95、合规）反向约束 L1–L3 的数据模型，避免返工。

二、Agent 团队分工（并行开发的核心）

把平台拆成 6 个相对独立的"域"，每个域配一个专职 Agent（或 Agent 小组），由"总架构 Agent"协调。 各 Agent 通过共享的事件总线协议 + 明确定义的接口契约解耦协作，而非互相改代码。

① 数据主线 Agent（底座组）：事件总线、WIP Engine、拓扑/主数据、时序+关系存储抽象、WS 协议。→ 所有其他 Agent 的依赖根。
② 智能引擎 Agent（质量/设备组）：SPC(补 Cpk/Ppk) · FDC(多变量) · PdM(补 RUL) · VM(补置信区间)。→ 领域层 Agent 的知识底座。
③ 排程仿真 Agent（APS 组）：有限产能排程、优化求解器接口、what-if 沙箱、负荷模型修正（瞬时占用率口径）。
④ 企业资源 Agent（ERP 组）：物料/BOM/成本/ARAP → 扩展 PLM/SCM 接口、ISA-95 第四/五层建模、标准会计凭证。
⑤ 孪生可视化 Agent（前端组）：三级孪生渲染升级、工厂级机理孪生、教学实验台 UI、社区沙盘打包。
⑥ Agent 平台 Agent（AI 内核组）：Agent 编排框架、对话/规则双模、领域知识库、人审锚点、记忆与工具调用。
协调机制：总架构 Agent 定义接口契约清单（事件类型、API schema、数据模型），各域 Agent 先对齐契约再并行实现； 每周做一次"契约集成日"验证跨域联通。这是避免 Agent 团队写出互相不兼容代码的关键。

三、四级开发路线图（分阶段）

阶段 0 · 地基加固（所有级共用，必须先做）

  • 定义跨域接口契约（事件 schema、API、数据模型）—— Agent 团队并行的前提。
  • 数据主线微服务化（MES/EAP/APS/ERP 拆独立进程 + 轻量 MQ），根治单进程单点。
  • 存储抽象层（关系 + 时序），让四级可切换不同后端。
  • 产出：可在本地一键拉起的多进程骨架 + 契约文档。

阶段 1 · L1 社区级（MVP 第一枪）

  • 把现有孪生 + 引擎打包成一键部署开源沙盘（Docker / 单命令）。
  • 接入对话式 Agent（轻量规则+检索优先，零 API 成本），能自然语言问答与引导。
  • 内置"AI 芯片典型工艺路线"默认场景。
  • 产出：github 开源项目 + 在线 demo + 对话助手。

阶段 2 · L2 教学级

  • 在 L1 上加课程模块 + 实验台 + 评测（如"用 SPC 拦截 CD 漂移"实验）。
  • Agent 升级为带教导师：提示不代做、个性化错题。
  • 引入 SEMI 标准工艺库（脱敏真实配方）。
  • 产出：院校可采购的教学平台 + 实验库。

阶段 3 · L3 专业级

  • 架构彻底微服务化 + OPC-UA/EDA 适配器（接真实设备/数据）。
  • 引擎模型深度升级（Cpk/RUL/置信区间）+ APS 优化求解器。
  • Agent 进入协作副驾态（半自治、人审锚点）。
  • 产出：工程师可用的专业工具，商业化起点。

阶段 4 · L4 工厂级

  • 多工厂/多租户、ISA-95 建模、等保/21 CFR Part 11、高可用。
  • Agent 自治体群 7×24 + 人在回路监督；真实 APC 闭环。
  • 产出：真实 FAB 上线运行的智能企业系统。

四、优先级与执行原则

优先级事项理由
P0阶段0 地基 + 接口契约Agent 团队并行的硬前提，不做则各域互相不兼容
P1L1 社区级 MVP零合规负担、快速出活、验证 Agent 接入范式、建生态
P1Agent 平台内核（双模）贯穿四级，越早定型越省返工
P2L2 教学级变现快、市场空白，依赖 L1
P3L3 专业级商业核心，但依赖架构拆分与模型深度
P3L4 工厂级价值最高、门槛最高，最后攻坚
执行铁律：① 先契约后实现；② 下层不依赖上层；③ 每阶段可独立验收、可回退； ④ Agent 团队只改自己域，跨域改动走"契约集成日"；⑤ 工厂级的合规/高可用要求从阶段0就反向约束数据模型。

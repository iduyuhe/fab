判定：AI 展示 + 一条统计闭环，非真正 AI-native。
平台拥有多个真实智能引擎与一个真实统计自控（SPC），但缺"模型输出 → 自动改写设备/排程/订单"的端到端自主链路。准确说法：具备智能分析层与单点统计自控的半自动 MES。

四、短板清单与补齐计划（全部自研）

P0 焊通 OTD 主轴（先做，AI 编排才有主轴可编）

  • P0-1 订单驱动生产：SO 创建 → EMIT soCreated → APS 排程 → engine.createWO 投料（替代 autoWo 凭空造单）。
  • P0-2 发运事件化 + 双域一致：EMIT shipment，WMS 发运订阅触发 ERP shipOrder，消除 ERP 虚拟发运 / WMS 物理发运背离。

  • P0-4 结算纠偏：lotDone 完工补 GL 凭证；AR 按真实 SO/发运自动开票，不再静默跳过。

P1 让 AI 真正闭环（AI 原生核心）

  • P1-1 FDC→自动响应：fdcAlarm 接回控制环（hold/隔离/通知）。
  • P1-2 APC 真实 setpoint：接 VM 预测+设备反馈写入真实 setpoint，可审计默认开。
  • P1-3 VM→APC feed；APS→dispatch：APS 按 SO 交期/优先级真实重排产线。
  • P1-4 Agent 升级为 OTD 编排器：白名单+人审下创建 SO、触发投料/发运、回答"我的订单到哪了"、异常自动建议并编排处置。

  • 成本按实际工艺路线计费（替代固定费率）；多租户/HA 视需求；文档与口径对齐（收回"AI-native 自主控制"等夸大表述）。

建议执行顺序

遵循项目"串主轴、不填层"范式：P0 是主轴本身断裂，必须先焊通；P1 把已具备的引擎接入这条主轴形成闭环；P2 做收尾与可信化。每一批改完均按 bin/start-community.sh 全量重启 + 验收脚本验证回归。
